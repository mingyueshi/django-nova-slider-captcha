# 普通表单 ARIA 关联修复与本地验证

本轮修复云端独立审核确认的低 P3 问题：Django 字段帮助/错误属性未到达实际可聚焦滑块。基线为 `7ea6a4900dde5438257999f6d3061785c092a5e4`，本地与官方 main 在开始时一致且工作树干净。这份报告是实施验证证据，不替代后续云端独立复核。

## 修改与复现

- `SliderCaptchaWidget` 只允许 `aria-describedby`、`aria-invalid` 进入模板，值保留 HTML 转义；不转发任意事件或 HTML 属性。
- Web Component 将外部描述 ID 与自身键盘说明 ID 去重合并到 range，并同步错误属性。初始定义、动态设置/移除、重复连接与重新插入均覆盖；各组件说明独立。
- 属性变化不调用重新发题，不改变 proof、generation、有效期或语言逻辑；服务端挑战、消费、限流、TTL、权限及版本号未修改。
- 两项新增 Django 测试覆盖无额外描述、仅帮助、仅错误、两者并存、带 prefix 的双字段，以及属性允许名单/转义。三项新增组件测试覆盖上述组合及动态/生命周期语义。DOM 联调新增四种真实 Django Form 渲染组合，每种验证两个 slider 的引用存在且文本非空。

新增回归在基线源码上失败：Django 属性缺失，组件仍只有内部 `nsc-instructions-*`。原始失败记录保留为 `baseline-forms.log`、`baseline-component.log`；它们是预期的修复前失败，不是最终测试结果。

源码验证从仓库根目录运行，`python` 指任务 Python，`$NOVA_ARIA_OUT` 指任务输出目录：

```sh
export DJANGO_SETTINGS_MODULE=tests.settings PYTHONPATH=src:.
export NOVA_TEST_DB="$NOVA_ARIA_OUT/source.sqlite3"
export COVERAGE_FILE="$NOVA_ARIA_OUT/.coverage"
python -m django test tests.test_forms --noinput -v 2
python -m coverage run -m django test tests --noinput -v 1
python -m coverage combine --keep
python -m coverage json -o "$NOVA_ARIA_OUT/coverage.json"
python scripts/check_coverage.py "$NOVA_ARIA_OUT/coverage.json"
python -m django check
python -m django makemigrations nova_slider_captcha --check --dry-run
ruff check .
npm test
NOVA_PYTHON="$(command -v python)" NOVA_DOM_REPORT="$NOVA_ARIA_OUT/dom.json" npm run test:dom
python -m build --no-isolation --outdir "$NOVA_ARIA_OUT/dist-final"
python -m twine check --strict "$NOVA_ARIA_OUT/dist-final/"*
python scripts/check_release.py --dist "$NOVA_ARIA_OUT/dist-final"
```

wheel 安装后用 `PYTHONPATH=.` 和另一任务数据库运行 `python -m django test tests --noinput -v 1`，先断言模块路径含 `site-packages`。真实 Chrome 使用独立会话及 loopback Django fixture：渲染带 prefix 的双 CAPTCHA 表单，并走真实本地 init/challenge API；断言脚本保存在证据目录 `browser-check.js`。仅观察到无关 favicon 404。
