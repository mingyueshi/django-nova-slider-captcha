## HTTPS Webhook

本次生成临时 CA 和含本机地址的服务端证书，接收地址使用回环 HTTPS。接收端从与请求事务独立的物理连接读取写库状态。签名按时间戳、点号和收到的原始正文字节计算 HMAC-SHA256。

- 三种写库均在默认关闭时零外发。验证和首次消费在各自写库事务提交前均无通知；提交后，接收端分别读到「已验证、未消费」和「已验证、已消费」。外层事务回滚、保存点回滚、多凭证表单回滚、提交前关闭回调均未产生对应通知。手动事务也核对了提交并恢复自动提交后的投递时机。
- 接收端返回 503、返回重定向、响应超时、证书不受信、连接失败或四个后台名额占满时，验证和凭证消费仍按数据库结果完成。重定向未被跟随，重放被拒绝，释放名额后后续通知恢复。另验证预派生子进程有独立的四个投递名额。
- 对全部实收通知核对方法、请求头、正文白名单、签名和通知 ID。正文只有 `event` 和 `notification_id`，同秒产生的通知 ID 也各异。检查未发现凭证、会话秘密、挑战 ID、用途、IP、密钥或私有请求标记。
- 另在 SQLite 上用同一用户会话串联素材撤下、用途禁用、事务回滚和接收端返回 503。禁用期间旧题及凭证被拒绝，回滚保持静默，提交后的凭证只成功消费一次。该流程实收的 3 个通知已单列在总数中。

本次验收范围为上述本地数据库实例、Chrome 和本机 TLS 接收端。跨主机复制、生产流量、外部接收方及远端 CI 未在本轮运行。未推送、打 tag 或发布。
